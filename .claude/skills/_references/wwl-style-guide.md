# WWL exam-item style rules (SC-500 working subset)

The **Microsoft Worldwide Learning Exam Writing Style Guide (WWL)** is authoritative for every exam item. The **Microsoft Writing Style Guide (MWSG)** governs prose where WWL is silent. When the two conflict inside an item, **WWL wins**. The two MWSG conventions WWL overrides: no contractions in items, and key names in ALL CAPS (TAB, ENTER, CTRL+ALT+DELETE).

## Question sentence

- Start with **What** (stand-alone interrogative pronoun) or **Which** (followed by a noun).
- Use **should** as the auxiliary. Do **NOT** use *can, must, might, do, would,* or *may* in the question sentence.
- Approved stems: *What should you do?* / *What should you recommend?* / *Which Azure service should you use?* / *Which two actions should you perform?* / *What are two possible ways to achieve this goal?*
- For Choose-N items, use a plural noun and embed the count in the stem (*Which two actions should you perform?*), never *Choose two* in parentheses.
- Avoid negatives. If unavoidable, **CAP** and **bold** the negative word (for example, **NOT**).
- Goal statements use *You need to ...* or *You need to ensure that ...*
- Use *of the following* only when answer choices are non-parallel.
- True/False stems are not allowed.

## Word usage (exam-specific)

- **named**, not *called*.
- **report**, not *complain*.
- Avoid **determine**. Use *verify, clarify, identify, set, discover, establish, calculate,* or *decide*.
- Avoid **may**. Use *can* (valid action) or *might* (possibility).
- Avoid **would** in questions; use *should*. Avoid **would like**; use *want* or *need*.
- Avoid **using** alone; use *by using*. Avoid **with** in place of *by using*.
- Avoid specific determiners: *all, none, only, always, never*.
- Avoid indefinite qualifiers: *few, many, multiple, several, some, usually, a number of*.
- Avoid parenthetical clauses; rewrite the sentence instead.
- *site* is logical; *location* is physical. Never interchange.
- Use **plural**; do not use *(s)* (write *client computers*, not *client computer(s)*).
- Present tense throughout. Avoid progressive (*is doing*) and perfect (*has done*) tenses.

## Answer choices

- Three to six choices per item. Single-correct items: 1 correct plus at least 2 distractors (default 4 choices, A-D).
- Choose-N items: *N* correct plus at least 2 distractors.
- Choices must be **mutually exclusive** (no overlap between any two).
- Choices must be **parallel** in form, length, detail, and grammatical structure.
- Choices must match the syntax of the question sentence (imperative stem yields imperative choices).
- Choices are either **all sentence fragments** (lowercase initial, no end punctuation) or **all complete sentences** (capitalized, period). Do not mix.
- No *all of the above*, *none of the above*, *both A and B*.
- Move any repeated lead-in wording from the choices up into the stem.
- Distractors must reference real Microsoft security services, Microsoft Entra features, Azure RBAC roles, Azure Policy effects, Defender for Cloud plans, network controls, or Sentinel features. Never invent fake names, roles, plans, or capabilities.
- No explanations inside answer choices. Explanations belong in the rationale.

## Rationale and references

- Exactly two sentences per choice: why it is correct or incorrect, plus context.
- Cite a real Microsoft Learn URL for the correct behavior. Never invent a URL.

## Formatting

- **Bold** for UI element names and PowerShell cmdlets.
- Input-neutral verbs: *select* (not click), *enter* (not type), *go to*, *open*, *close*.
- Sentence-style capitalization except for proper nouns and product names.
- Oxford comma in all lists. No contractions.
